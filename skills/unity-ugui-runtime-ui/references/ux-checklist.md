# UX設計チェックリスト

このファイルは `unity-ugui-runtime-ui` スキルの F2：UX設計（`designUx`、requirements.md 5.3節）が
定める8手順それぞれに対応するチェックリストである。手順の判断基準そのものは `SKILL.md` 本文
（F2節・設計原則12項目）に常設されているため、ここでは重複させず、各手順の出力が満たすべき
条件を確認項目として列挙する。

## 読み込み条件

`SKILL.md` の「参照ファイルの読み込み条件」表のとおり、以下のときに読む。それ以外は `SKILL.md`
本文のみで手順を完結させる。

- 構築モードで画面を2つ以上扱うとき
- レビューモードの常時

## 使い方

- **構築・改修モード**：F2の各手順を実行した直後に、対応する節のチェック項目をすべて確認する。
  未チェックの項目が残る場合、その手順に戻って設計メモを補う。
- **レビューモード**：既存実装を1手順ずつこのチェックリストと突き合わせ、満たさない項目を
  「所見」として重大度（重大／改善／提案。判定基準は `references/review-rubric.md`）とともに
  列挙する。改修モードへ続く場合、要求範囲内の所見のみをF3以降で扱う（設計原則11）。

---

## 1. 画面インベントリ

要求から画面・パネル・部品を列挙し、目的と主要操作を定める手順（5.3節手順1）の確認項目。

- [ ] 要求に現れる画面・パネル・モーダル・トーストなどの部品をすべて列挙したか
- [ ] 要求に無い画面を推測で追加していないか
- [ ] 各項目の目的を1文で定めたか（2文以上に広がっていないか）
- [ ] 各項目の主要操作を3つ以内に絞ったか
- [ ] 一覧に挙げた部品が、後続の手順2〜8ですべて扱われているか（列挙だけで終わっていないか）

## 2. 情報階層

各画面の視線の起点と主要操作を1つに絞る手順（5.3節手順2）の確認項目。

- [ ] 各画面で最も重要な情報・操作を1つ選んだか
- [ ] それを視線の起点（左上または中央）に配置したか
- [ ] 主要操作が1画面に1つだけになっているか（同格の主要操作が並んでいないか）
- [ ] 二次操作を主要操作より視覚的に弱めたか（サイズ・彩度・配置のいずれかで区別）
- [ ] 最重要の情報・操作が装飾要素（背景画像・アイコン等）に埋もれていないか

## 3. レイアウト方式の選択

画面ごとにアンカー固定／LayoutGroup／ScrollRectを選ぶ手順（5.3節手順3）の確認項目。
判断基準の詳細は `references/layout.md` を参照する（可変要素数の画面・レイアウト崩れの改修時）。

- [ ] 要素数が固定かつ少数の画面にアンカー固定を選んだか
- [ ] 要素数が可変または並列に配置する画面にLayoutGroupを選んだか
- [ ] 一覧を表示する画面にScrollRectを選んだか
- [ ] 同一階層でアンカー固定とLayoutGroupを混在させていないか
- [ ] 件数が不明または50件を超える一覧に、行の使い回し（プール）を設計に含めたか
      （50件超は `references/webgl-runtime.md` の対象）

## 4. 状態一覧

初期・読込中・空・エラー・無効・成功の各状態を定める手順（5.3節手順4）の確認項目。

- [ ] 初期状態の表示内容を定めたか
- [ ] 読込中状態の表示（インジケータ等）と文言を定めたか
- [ ] 空状態の表示と文言を、データを扱う画面で省略せずに定めたか
- [ ] エラー状態の表示と文言を、データを扱う画面で省略せずに定めたか
- [ ] 無効状態（操作不可）の表示を定めたか
- [ ] 成功状態の表示と文言を定めたか
- [ ] `Render(state)` が未定義の状態を例外にせず「空」表示に倒す設計になっているか

## 5. フィードバック

押下遷移・確認・結果通知を定める手順（5.3節手順5）の確認項目。

- [ ] 押下可能な要素すべてに押下遷移（色または拡縮）があるか
- [ ] 破壊的操作（削除・上書き・送信の取消不可な確定等）に確認を挟んだか
- [ ] 結果通知をトーストまたはインライン表示にしたか
- [ ] 結果通知にモーダルを使っていないか（モーダルは入力の中断が必要な場合に限定したか）
- [ ] 同一画面でモーダルを多用していないか（1画面の主要導線に対して1つを超えて重ねていないか）

## 6. 導線

戻る手段・モーダルの閉じ方・キーボードナビゲーションを定める手順（5.3節手順6）の確認項目。

- [ ] すべての画面・モーダルに戻る手段があるか
- [ ] モーダルが背景タップまたは閉じるボタンで閉じられるか
- [ ] キーボード操作が要求される場合、`Selectable` のナビゲーション（`Navigation.Explicit` 等）
      を明示設定したか
- [ ] 自動ナビゲーション（`Navigation.Automatic`）に頼ったまま放置していないか
- [ ] フォーカスの初期位置と、モーダルを閉じたあとのフォーカス復帰先を定めたか
      （キーボード操作が要求される場合）

## 7. 追従規則

CanvasScalerの設定とアンカー／コンテナの使い分けを定める手順（5.3節手順7）の確認項目。
詳細は `references/layout.md` を参照する。

- [ ] `CanvasScaler` が `ScaleWithScreenSize` になっているか
- [ ] 参照解像度が前提セット（F1）の値と一致しているか
- [ ] マッチ値が横長で0.5・縦長で0（幅基準）になっているか
- [ ] 画面の端に寄せる要素をアンカーで制御しているか
- [ ] 中央の内容を最大幅を持つコンテナで制御しているか（アンカー固定とLayoutGroupを
      同一階層で混在させていないか、手順3と重複確認）

## 8. アクセシビリティ判定

タップ領域・文字サイズ・コントラスト比・色以外の区別を判定する手順（5.3節手順8）の確認項目。
数値基準は設計原則（不変条件10）と同一であり、`scripts/check_contrast.py`（コントラスト比）・
`scripts/lint_ugui_csharp.py`（テーマ外の色リテラル検出）で機械的にも検査される。

- [ ] すべてのタップ領域が参照解像度で44px四方以上か
- [ ] 本文の最小文字サイズが参照解像度で14px以上か
- [ ] 前景・背景のすべての組み合わせでコントラスト比が4.5以上か
- [ ] 状態（有効・無効・エラー・成功等）の区別が色のみに依っていないか
      （アイコン・文言・形状のいずれかを併用しているか）
- [ ] テーマの色がこれらの判定を満たす組み合わせのみで構成されているか
      （判定を満たさない色をテーマに追加していないか）

## レビューモードでの記録形式

上記1〜8の各チェック項目のうち満たさないものを、以下の形式で所見として記録する。

| 手順 | 所見 | 重大度 | 根拠（本チェックリストの項目） |
|---|---|---|---|
| `<例：4. 状態一覧>` | `<例：一覧画面にエラー状態の表示が無い>` | `<重大 \| 改善 \| 提案>` | `<例：データを扱う画面で空・エラーを省略せずに定めたか>` |

重大度の判定基準（重大＝動作しない・操作できない、改善＝使いにくい・崩れる、提案＝保守性）は
`references/review-rubric.md` に従う。改修モードへ続く場合、重大所見のうち要求範囲内のものだけを
F3以降で扱う。
