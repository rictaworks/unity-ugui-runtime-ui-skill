# text-and-fonts.md

Text（`UnityEngine.UI.Text`）とTextMeshPro（TMPro）の選択基準、フォント同梱の扱い、CJK文字体系ゲート、WebGLでのフォントフォールバック制約を扱う。

読み込み条件（`SKILL.md`）：CJK文字を扱うとき、既存コードが`TMPro`を使用しているとき。

## Text/TMPの選択基準

`SKILL.md` F1手順4の判定をそのまま適用する。ここでは判断の根拠と境界条件を補う。

1. **既定はText。** `UnityEngine.UI.Text`を既定のテキスト方式とする。TextMeshProへの切り替えは、次の2条件を**両方**満たす場合に限る。
   - 既存コードが`TMPro`名前空間（`TMPro.TextMeshProUGUI`等）を使用している。
   - 表示対象の文字体系をカバーするTMPフォントアセット（`TMP_FontAsset`）が`Assets/`配下に既に存在する。
2. **フォントアセットの生成は行わない。** TMPフォントアセットの生成（Font Asset Creator相当の処理）は範囲外（不変条件8）。既存アセットが文字体系をカバーしない場合、TMPへは切り替えず、後述の文字体系ゲートに従ってTextのまま処理を続けるか停止する。
3. **既存コードがTMPを使用しない場合は、要求がTMPを名指ししていてもTextを用いる。** 新規にTMPro依存を持ち込むと、フォントアセット生成という範囲外作業を要求することになるため。
4. **画面内でTextとTMPを混在させない。** 1画面（1つの`<ScreenName>Screen`）の内部では、判定結果のどちらか一方に統一する。既存規約が画面ごとに異なる場合はそのまま踏襲し、統一を目的とした改修は行わない（改修モードは要求範囲外を変更しない）。
5. **`UiFactory.CreateText`はFontを引数として要求する。** フォント解決（手順1〜4の結果、どのFontアセットを使うか）は呼び出し側の責務とし、`UiFactory`内でフォールバックしない（フォールバック禁止）。

## フォント同梱の扱い

1. **テンプレートにフォントファイルを含めない。** `assets/`配下のテンプレート（`UiTheme.cs.tmpl`等）はフォントファイル（`.ttf`・`.otf`）もTMPフォントアセットも同梱しない（15章）。
2. **同梱してよいのは、利用者がライセンスを確認したフォントのみ。** 第三者フォントの再配布条件はフォントごとに異なるため、確認済みの判断はスキルではなく利用者が行う。スキルはフォントの選定・ダウンロード・ライセンス可否判定を代行しない。
3. **配置先は`Assets/Resources/Fonts/`。** F1手順5（文字体系ゲート）で停止した場合、利用者に求める配置先はここに固定する。`Resources/`配下に置くのは、`Font.Load`系APIやTMPのフォント参照解決を実行時に安定させるため。
4. **配置後の再開。** フォントファイルまたはTMPフォントアセットが配置されたことを確認したら、F1（前提収集）からやり直す。既存の中断前の成果物を流用せず、既存規約探索からやり直すことで、フォント方式の判定に矛盾が生じないようにする。

## CJK文字体系ゲート（不変条件7）

`SKILL.md` F1手順5・不変条件7の判定手順と一致させる。

1. **判定対象。** 要求文・既存文言・仕様書のいずれかにCJK文字（日本語・中国語・韓国語の文字。ひらがな・カタカナ・漢字・ハングルを含む）が含まれる場合に判定を行う。ラテン文字のみの要求では本ゲートを評価しない。
2. **存在確認。** `Resources/`配下に、その文字体系のグリフを含むフォントファイル（`.ttf`・`.otf`）が存在するか、または対応するTMPフォントアセットが存在するかを確認する。フォントがそのグリフをカバーするかはファイル名や配置場所からの推測に留めず、判断できない場合は「不明」として扱い、存在確認を満たしたとはしない。
3. **不足時は停止する。** 対応フォントが見つからない場合、以降の手順（F2以降）を実行せず停止する。停止時に求める内容は「フォントファイルの配置（ライセンス確認済みのものを`Assets/Resources/Fonts/`へ）」の1点とする。
4. **組み込みフォントで代替しない。** `LegacyRuntime.ttf`（Unity組み込み）はCJKグリフを含まない。代替や部分表示（文字化け・豆腐（`□`）表示）を許容せず、停止する。
5. **停止は最終判断ではない。** フォント配置後にF1からやり直せば処理を継続できる旨を、停止時の報告に添える。

### 判定の擬似コード

```
if 要求文またはUI文言にCJK文字を含む:
    if Resources配下に対応フォントファイル or 対応TMPフォントアセットが存在する:
        文字体系ゲート: 通過
    else:
        文字体系ゲート: 停止（LegacyRuntime.ttfでの代替は行わない）
else:
    文字体系ゲート: 評価対象外（既定フォントで続行）
```

## WebGLでのフォントフォールバック制約

1. **OSフォントへのフォールバックが無い。** WebGLビルドはOSにインストールされたフォントへ実行時にフォールバックできない。デスクトップ・モバイルのネイティブビルドと異なり、「端末に日本語フォントが入っているから表示できる」という前提は成立しない。
2. **表示に使う文字体系のグリフはビルドに含める必要がある。** Textが参照する`Font`アセット、またはTMPフォントアセットが、実際に表示する文字のグリフを持っていなければ、その文字はWebGL上で表示されない（豆腐表示または空白になる）。これは文字体系ゲート（不変条件7）がビルド前の静的検査ではなく実行時前提の確認である理由でもある。
3. **動的フォント生成の負荷。** `UnityEngine.UI.Text`はOSフォントのラスタライズに依存する部分があるが、WebGLではこの経路が制限される。文字種が多い（CJK漢字等）場合、TMPフォントアセット（事前生成済みアトラス）の方が実行時負荷・表示安定性の面で有利になりやすい。ただし本スキルはTMPフォントアセットの生成を行わない（不変条件8）ため、既存アセットが無ければこの選択肢は取れない。
4. **フォントサイズのアトラス依存（TMP利用時）。** TMPフォントアセットは生成時のアトラスサイズ・グリフ範囲に依存する。動的フォントサイズ拡張（Dynamic OS Font Fallback相当の機能）はWebGLでは前提にしない。既存アセットに含まれないグリフ・サイズが必要な場合は、フォントアセットの再生成が必要になるが、これは範囲外であるため、利用者への申し送り事項として報告に明記する。

## 報告への反映

- フォント未同梱・文字体系ゲート停止・TMPフォントアセットの制約は、F6報告の「既知の制限」に記す（`SKILL.md` F6手順5）。
- 停止に至った場合は、F6以降を実行していないことを明記し、停止した手順（F1手順5）と、利用者に求めた配置内容を記す。
